# История версий ядра

Версия ядра — в `VERSION`. Запись добавляет `release_core.py --bump`, перечень изменений пишет человек по-русски.
Правило: изменение `tools/*.py` и `tools/*.html` уезжает в мастер только вместе со сменой версии (см. `openspec/specs/core-versioning/spec.md`).

## 1.4.0 — 2026-11-26

- Источник хранит массив `files` (`path`, `sha256`, `role`) вместо `vault_path`/`sha256`: подборка из нескольких частей больше не живёт в примечании.
- Перечень ролей файла — `file_roles` в реестре (`original`, `scans`, `transcription`, `photos`, `reference`, `appendix`, `other`).
- Проверка источников сверяет каждый файл: потерянная часть, расхождение sha256, дубль пути внутри источника — ошибки; файл в двух источниках — предупреждение.
- `intake.py inbox` — обзор папки «Входящие для разбора» в Obsidian: размер, sha256, известно/ново, предложенный slug; ничего не меняет.
- `intake.py adopt` — артефакт по файлу из хранилища (`from_vault: true`), без копирования в репозиторий.
- `intake.py apply` умеет виды-источники (`personal-letters`, `museum-photo`, `archive-reply`): проверка схемы, перенос файла в `Исходники/`, запись в `data/sources.json`, откат при ошибке; `--source-id` дополняет существующий источник.
- Новый документ `docs/developers/obsidian-flow.md` — устройство хранилища и конвейер.

## 1.3.0 — 2026-11-26

- Вид источника `personal-letters` (личные письма и семейные материалы): файловые требования (`vault_path`, `sha256`) распространяются на него как на прочие файловые виды.
- Вид свидетельства `personal-letter` («Личное письмо») и ключ утверждений персоны `correspondence` («Пункты переписки»).
- Проверка расхождений не считает `correspondence` конфликтом: адреса сменяются последовательно, а не спорят друг с другом.
- Отчёт о людях печатает адрес переписки рядом с периодом.

## 1.2.1 — 2026-11-26

- `guard_core.py` запрещает коммит изменений ядра прямо в мастер: правило «ядро — в ветке» теперь проверяется, а не подразумевается (раньше хук ловил только отсутствие смены версии, и релизный коммит в мастере проходил).
- Проверка вынесена в `branch_violation()` и покрыта тестом: мастер + файл ядра — отказ, ветка — пропуск, мастер + только данные — пропуск.

## 1.2.0 — 2026-11-26

- Добавлены шаги с моделью `tools/ai_steps.py`: `propose` (скил + вход → предложение), `review` (построчный разбор), `apply-proposal` (применение по порогу уверенности).
- Скилы как контракты в `tools/skills/*.yaml`: `extract-facts` (текст → факты с цитатами), `transcribe-weak-scan` (изображение → текст с пометками сомнения).
- Проверки предложения: цитата по нормализованному OCR-тексту, место по справочнику, обязательная дата, дубликат события, низкая уверенность.
- Модель необязательна: при отсутствии `VOV_AI_*` пишется бандл запроса, ответ принимается через `--ingest`; в журнал пишутся модель, хеш промпта и версия ядра.
- `intake.py status` понимает шаги предложения: состояние `proposed` и `applied` теперь выводится и из записей `propose:`/`apply-proposal:`.

## 1.1.0 — 2026-11-26

- Введён входной конвейер `tools/intake.py`: артефакт кладётся папкой в `inbox/` с манифестом `artifact.yaml`, состояние выводится из журнала, а не хранится в манифесте.
- `drop` создаёт артефакт и манифест-заготовку, `status` показывает шаг, `scan` делает офлайн-разбор (хеши, формат по сигнатуре, размеры, страницы и текстовый слой PDF, слайды PPTX, OCR с оценкой разборчивости, дедуп по sha и по реквизитам), `apply` переносит файл в Obsidian и вносит документ, `reject` закрывает артефакт с причиной.
- Журнал `data/intake/journal.jsonl` — append-only; битая строка сообщается с номером, а не пропускается.
- Применение проверяет запись схемой документа с реестром схем (без похода в сеть) и откатывает копию файла при нарушении; повторный `apply` документ не дублирует.

## 1.0.0 — 2026-11-26

- Введена версия ядра: `tools/VERSION`, чтение через `tools/coremeta.py`, формат semver проверяется.
- Валидатор печатает версию ядра первой строкой.
- Сборка вписывает версию в заголовки сгенерированных md и в свойства GeoJSON-коллекций; `--check` считает артефакт другой версии расхождением.
- Добавлены релизная процедура `tools/release_core.py` и защита правила `tools/guard_core.py` (+ установщик pre-commit хука).
