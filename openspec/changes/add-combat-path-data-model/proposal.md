# Proposal

## Why

Проект задуман как анимация фронта, но всё, что в ней будет показано, обязано быть проверяемым — а исходные документы противоречат друг другу: по одному деду четыре разные даты гибели (декабрь 1941 / январь-февраль 1942 / февраль-март 1942 / август 1942). Без формализованной модели данных и обязательной ссылки «факт → производная md → исходник» карта и таймлайн будут опираться на непроверяемые утверждения, а расхождения — молча схлопываться в одну «удобную» версию.

## What Changes

- Вводится модель данных боевого пути: соединения и части, события (бой, приказ, перемещение, потеря, награждение), интервалы дат с явной неопределённостью, геометрия (точка, линия, маршрут, полигон), привязка к датам.
- Каждый факт (поле, не весь файл) обязан иметь провенанс: ссылку на производную в `docs/sources/` с локатором (страница, слайд, абзац) и через неё — на исходник в Obsidian.
- Вводится статус достоверности факта и явные конфликты: конкурирующие значения одного поля сосуществуют с указанием источника, без автоматического «выбора победителя».
- Данные хранятся в `data/` машиночитаемо (JSON + GeoJSON), сводка для человека генерируется в markdown.
- Вводится валидатор: непроставленный провенанс, ссылка на несуществующий файл, конфликт без источников — ошибка, а не предупреждение.

## Capabilities

### New Capabilities

- `combat-path-data`: структура набора данных боевого пути — соединения, события, интервалы дат, геометрия, точность локализации; правила, по которым анимация сможет читать эти данные.
- `source-provenance`: обязательная связь каждого факта с производной и исходником, статусы выверки, правила фиксации расхождений между источниками.

### Modified Capabilities

Нет — проект новый, спецификаций пока не существует.

## Impact

- `data/` — новые схемы и файлы данных боевого пути.
- `tools/` — валидатор провенанса и сборка сводки.
- `docs/sources/` — существующие производные не переписываются, но получают стабильные идентификаторы для ссылок.
- `docs/research/` — сводка и таблица расхождений становятся генерируемыми из данных, а не ручными.
- Будущие шаги (прототип карты, анимация) получают контракт, на который можно ссылаться; вне этого change они не реализуются.
