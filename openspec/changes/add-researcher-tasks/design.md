# Design

## Что такое задача

Задача — markdown-файл с YAML-шапкой. Шапка машиночитаемая (по ней строится индекс и проверяются ожидания), тело — для человека: зачем, что, чем, критерий.

```markdown
---
id: task-georef-klin-vi1942
kind: georeference-sheet
status: open
priority: high
created: 2026-11-27
about:
  source_id: src-mapywig-100k
  file: "Хобби/365сд/Исходники/Карты 1:100 000 — немецкие 1942/Russland_100K_O-37-XVI-Ost_Klin_VI.1942.jpg"
tool: qgis-georeferencer
estimate_min: 60
depends_on: []
expects:
  - path: "Хобби/365сд/Входящие для разбора/klin_VI42.points"
    why: "GCP из Georeferencer: по ним видно, какими ориентирами привязан лист"
    required: true
  - path: "Хобби/365сд/Входящие для разбора/klin_VI42.tif"
    why: "привязанный GeoTIFF (LZW, EPSG:3857) — основа для снятия координат"
    required: true
done_when:
  - "в data/calibration/index.json появилась запись status=georef с rms_m"
  - "validate и build --check зелёные"
---
```

## Поля шапки

| Поле | Смысл |
|---|---|
| `id` | стабильный; повторный прогон не создаёт второй файл |
| `kind` | `georeference-sheet`, `digitize-places`, `trace-positions` — из реестра `task_kinds` |
| `status` | `open`, `in-work`, `done`, `dropped` |
| `priority` | `high`, `normal`, `low` — чем раньше разблокирует другие задачи, тем выше |
| `about` | что именно: `source_id`, `file`, `place_ids`, `document_requisites` |
| `tool` | чем делать: `qgis-georeferencer`, `trace_front_line.html`, `intake.py` |
| `estimate_min` | честная оценка в минутах, чтобы человек планировал вечер, а не «на пять минут» |
| `depends_on` | задачи, без которых эта не имеет смысла |
| `expects` | файлы, которые движок ждёт во входящих: путь, зачем, обязательность |
| `done_when` | проверяемые условия закрытия |

## Генераторы

Задачи порождаются из состояния данных, а не пишутся руками — иначе через месяц в них будет то, что уже сделано.

1. **`georeference-sheet`** — для каждого файла источника вида `map`/`historical-map`, у которого нет записи в `data/calibration/index.json` со статусом `georef`. Приоритет `high`, если файл покрывает период с положениями частей или событиями.
2. **`digitize-places`** — для каждого источника, у которого есть привязанный лист, и мест `state: unfound`, на которые ссылаются положения частей или события. Одна задача на источник, места — таблицей с пустой графой координат. `depends_on` — задача привязки этого листа.
3. **`trace-positions`** — для привязанного листа, если с него ещё нет ни одного положения с `basis: map`.

Генераторы идемпотентны: файл задачи создаётся, если его нет; существующий файл со статусом `open`/`in-work` не перезаписывается (человек мог дописать свои заметки), но получает пометку, если изменились ожидания. `done`/`dropped` не трогаются вовсе.

## Состояние привязки

`data/calibration/index.json` — единственное место, где сказано, что лист привязан:

```jsonc
{
  "sheets": [
    {
      "source_id": "src-mapywig-100k",
      "file": "…Klin_VI.1942.jpg",
      "status": "none",            // none | georef | checked
      "calibration": null,          // путь к GCP/полиному, когда появится
      "gcp": 0,
      "rms_m": null,
      "note": "привязки нет; координаты пунктов брать неоткуда"
    }
  ]
}
```

`status: georef` ставит человек (или движок после приёма `.points`); `checked` — после контрольной проверки по независимому ориентиру. Пока `none`, задача `digitize-places` не может быть выполнена, и это написано в её шапке через `depends_on`.

Почему отдельный файл, а не поле у источника: у источника может быть несколько листов, привязываются листы по отдельности, а `data/sources.json` — про происхождение, не про обработку.

## Закрытие

`tasks.py close <id>` ставит `done` и дату, но только если ожидаемые файлы найдены (в входящих или уже в хранилище) и `validate` зелёный. Иначе — отказ с перечнем недостающего: закрытая задача без файла — это ложь, из-за которой пробел исчезнет из поля зрения.

## Куда пишется

- `tasks/<id>.md` — в репозиторий: задачи версионируются вместе с данными, видно, когда появились и когда закрылись.
- `~/Documents/Obsidian Vault/Хобби/365сд/Задачи для исследователя/` — зеркало для чтения и отметок с телефона; правится только через `tasks.py sync`, чтобы не разъехалось.
- `tasks/index.json` — сводка: id, kind, status, priority, depends_on, дата создания/закрытия.

## Чего здесь нет

- Нет исполнителя задач: движок не привязывает листы за человека и не обводит полосы «примерно». Задача формулирует требование и проверяет результат.
- Нет сроков и напоминаний: это не трекер, а список того, что нужно добыть, с критерием приёмки.
- Нет фактов: ни одно поле задачи не попадает в `data/` как свидетельство.
