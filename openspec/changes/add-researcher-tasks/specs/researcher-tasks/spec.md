# Spec Delta

## Purpose

Обратный канал к инбоксу: движок сообщает исследователю, что именно нужно добыть, зачем, с какой детализацией и в каком виде вернуть, — и закрывает требование только по принятому файлу.

## ADDED Requirements

### Requirement: Задача называет зачем, что, чем и что ждём

Каждая задача SHALL содержать разделы: что станет возможным после её выполнения и что сейчас невозможно; перечень добываемого с требуемой детализацией и допуском; инструмент и пошаговый сценарий работы; перечень ожидаемых файлов с путём приёма; проверяемый критерий готовности.

#### Scenario: Задача на привязку листа
- **WHEN** лист карты используется для съёмки координат, но привязки нет
- **THEN** задача называет лист, ожидаемую точность (метры), инструмент, число опорных точек, имена `.points` и GeoTIFF, которые ждут во входящих, и условия закрытия

#### Scenario: Задача без критерия готовности
- **WHEN** в задаче нет проверяемого `done_when`
- **THEN** проверка задач отклоняет файл: «задача без критерия не закрывается»

### Requirement: Задачи порождаются из состояния данных

Генераторы SHALL создавать задачи из пробелов датасета: отсутствие привязки листа, пункты без координат, на которые ссылаются положения или события, привязанный лист без оцифрованных полос.

#### Scenario: Пункт без координат
- **WHEN** положение части ссылается на пункт со `state: unfound`
- **THEN** появляется задача на привязку пунктов этого листа, и в ней перечислены только те пункты, которые действительно нужны данным

#### Scenario: Всё уже сделано
- **WHEN** у листа есть привязка `status: georef` и с него есть положения
- **THEN** новые задачи по этому листу не создаются

### Requirement: Повторный прогон не плодит и не затирает задачи

Повторный запуск генератора SHALL NOT создавать дубликат и SHALL NOT перезаписывать задачу в статусе `in-work`, где человек мог дописать заметки; закрытые и отклонённые задачи не изменяются.

#### Scenario: Задача уже открыта
- **WHEN** задача с тем же `id` существует в статусе `open`
- **THEN** файл остаётся как есть, в индекс попадает одна запись

#### Scenario: Задача закрыта, пробел вернулся
- **WHEN** задача была закрыта, но данные снова показывают пробел
- **THEN** создаётся новая задача с новым `created`, а старая остаётся в истории

### Requirement: Ответ приходит существующим инбоксом

Ожидаемые файлы SHALL приниматься через `Хобби/365сд/Входящие для разбора` — отдельный канал не создаётся; путь и имя файла указаны в задаче заранее, чтобы приём не требовал догадок.

#### Scenario: Файл назван иначе
- **WHEN** во входящих лежит файл с другим именем, но того же смысла
- **THEN** задача не закрывается автоматически; человек получает сообщение, что имя не совпало с ожидаемым

### Requirement: Закрытие только по проверенному результату

`close` SHALL отказывать, если ожидаемые обязательные файлы не найдены или проверка датасета красная; отказ SHALL перечислять недостающее.

#### Scenario: Привязка без файла
- **WHEN** просят закрыть задачу на привязку, а GeoTIFF во входящих нет
- **THEN** закрытие отклоняется с перечнем отсутствующих файлов, статус остаётся `open`

### Requirement: Состояние задач не смешивается с фактами

Файлы задач и индекс SHALL храниться вне `data/` и SHALL NOT проверяться валидатором как свидетельства; задачи не попадают в сборку артефактов истории.

#### Scenario: Валидатор датасета
- **WHEN** запускается `validate.py`
- **THEN** ни одна задача не считается источником, а её отсутствие не влияет на проверку данных
