# Spec Delta

## Purpose

Шаги с моделью: скилы описывают контракт, модель отдаёт предложение, инструмент проверяет его на цитатах и справочнике, применение к данным — отдельная команда с порогом уверенности. Модель никогда не пишет в базу напрямую.

## ADDED Requirements

### Requirement: Скил — контракт шага

Каждый шаг с моделью SHALL описываться файлом `tools/skills/<имя>.yaml` с полями `name`, `input` (text или image), `output` (JSON Schema), `prompt` и правилами. Скил без схемы выхода или с именем, не совпадающим с файлом, не принимается.

#### Scenario: Скил неизвестен
- **WHEN** запускают `propose --step classify-magic`, а такого файла нет
- **THEN** инструмент печатает список доступных скилов и завершается с ошибкой

#### Scenario: Схема выхода отсутствует
- **WHEN** в скиле нет блока `output`
- **THEN** загрузка скила отклоняется с указанием поля

### Requirement: Модель не пишет в данные

Результат шага SHALL сохраняться только в `data/proposals/<slug>/` вместе с именем модели, хешем промпта и версией ядра. Запись в `data/events/**` и `data/documents.json` возможна только командой `apply-proposal`.

#### Scenario: Предложение без применения
- **WHEN** `propose` отработал успешно
- **THEN** файлы событий не меняются, а в журнале появляется запись `propose:<скил>`

#### Scenario: Модель не настроена
- **WHEN** переменные `VOV_AI_BASE_URL`, `VOV_AI_API_KEY`, `VOV_AI_MODEL` не заданы
- **THEN** `propose` записывает бандл запроса и подсказывает подать ответ через `--ingest`

### Requirement: Цитата проверяется по входному тексту

Каждая позиция предложения SHALL содержать цитату, которая после нормализации (регистр, ё/е, пробелы) присутствует во входном тексте. Позиция с неподтверждённой цитатой не применяется.

#### Scenario: Цитата выдумана
- **WHEN** в позиции цитата, которой нет в тексте листа
- **THEN** проверка помечает позицию как непригодную и называет причину

#### Scenario: Цитата с опечатками OCR
- **WHEN** цитата дословно повторяет распознанный текст с его опечатками
- **THEN** цитата считается подтверждённой (сравнение идёт с OCR-текстом, а не с исправленным)

### Requirement: Место и дата проверяются до применения

Позиция с названным местом SHALL находить его в `data/places.json` по точному совпадению названия; позиция без даты не применяется. Событие, совпадающее с существующим по дате и формулировке, помечается как дубликат.

#### Scenario: Места нет в справочнике
- **WHEN** позиция называет населённый пункт, которого нет в справочнике
- **THEN** позиция помечается непригодной с указанием названия

#### Scenario: Дубликат события
- **WHEN** позиция повторяет уже внесённое событие той же даты
- **THEN** проверка сообщает о дубликате и не даёт применить позицию

### Requirement: Применение по порогу уверенности

`apply-proposal` SHALL применять только пригодные позиции с уверенностью не ниже порога (по умолчанию 0.7), записывать события через те же схемы и откатывать изменения, если данные не прошли проверку. Повторный запуск не создаёт второе событие.

#### Scenario: Уверенность ниже порога
- **WHEN** у позиции уверенность 0.65, а порог 0.7
- **THEN** позиция пропускается, причина печатается в отчёте

#### Scenario: Схема не приняла событие
- **WHEN** после вставки событий валидатор сообщает нарушение
- **THEN** файлы событий восстанавливаются из резервной копии, в журнале остаётся запись об ошибке

#### Scenario: Повторное применение
- **WHEN** `apply-proposal` запущен второй раз по тому же предложению
- **THEN** новые события не создаются, отчёт говорит «уже применено»
