# Proposal

## Why

Два связанных недостатка.

**Первый: у источника один файл.** `data/sources.json` требует `vault_path` + `sha256`, то есть ровно один файл на источник. Подборка писем Бизяева состоит из трёх частей (расшифровки, портреты со справкой, оригиналы на 21 странице), и сейчас вторая часть живёт в `note` текстом. Любая подборка — альбом, пачка фотографий, многотомное дело — ломает контракт.

**Второй: у Obsidian нет входа.** Файлы в хранилище попадают вручную и в произвольные папки; инструмент узнаёт о них, только когда человек вручную впишет путь. При этом `intake.py` умеет `apply` лишь для документов портала (пишет в `data/documents.json`) и не знает видов `personal-letters`, `museum-photo`, `archive-reply` — то есть личные материалы проходят мимо конвейера.

Нужен единый вход: папка «Входящие для разбора» в Obsidian → инструмент показывает, что там лежит, ловит уже известные файлы по sha256 → `apply` переносит файл в целевую папку хранилища и вносит источник в реестр.

## What Changes

- `source` получает массив `files: [{path, sha256, role}]` (минимум один файл); `vault_path` и `sha256` уходят, десять существующих источников мигрируют.
- `role` описывает, что это за файл: `original`, `scans`, `transcription`, `photos`, `reference`, `appendix`, `other`.
- `intake.py` получает команду `inbox`: обход папки «Входящие для разбора» в хранилище, размер, sha256, отметка «уже известно» по реестру источников и документам.
- `intake.py adopt`: завести артефакт по файлу из хранилища, не копируя его в репозиторий (крупные PDF остаются на месте).
- `intake.py apply` для видов-источников: переносит файл из «Входящих» в целевую папку, сверяет sha256 до и после, вносит источник в `data/sources.json`, при нарушении схемы откатывает перенос.
- Виды инбокса расширяются: `personal-letters`, `museum-photo`, `archive-reply`.
- Новый документ `docs/developers/obsidian-flow.md`: устройство хранилища, папка входящих, правила имён, что делает инструмент и чего он не делает.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `source-provenance`: источник хранит список файлов с ролями; проверка сверяет каждый файл, а не один.
- `source-intake`: входящие в хранилище становятся штатной точкой входа; `apply` умеет вносить источники, а не только документы портала.
