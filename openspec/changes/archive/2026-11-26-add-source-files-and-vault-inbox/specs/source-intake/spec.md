# Spec Delta

## Purpose

Входящие в Obsidian становятся штатной точкой входа: человек кладёт файлы в одну папку, инструмент показывает, что там лежит, узнаёт уже известное по sha256 и переносит разобранное в целевую папку хранилища.

## ADDED Requirements

### Requirement: Входящие в хранилище — точка входа

Инструмент SHALL иметь команду обзора папки «Входящие для разбора» в хранилище, которая печатает для каждого файла размер, sha256 и признак «известен/нов» по реестру источников и документам, и SHALL NOT изменять файлы или данные при обзоре.

#### Scenario: Обзор входящих
- **WHEN** в папке входящих лежат два файла, один из которых уже зарегистрирован
- **THEN** обзор показывает оба, у известного стоит отметка «известен», у нового — предложенный slug

#### Scenario: Пустая папка
- **WHEN** папка входящих пуста или отсутствует
- **THEN** обзор сообщает об этом и не считает это ошибкой

### Requirement: Артефакт из хранилища не копируется в репозиторий

Для файлов, лежащих в хранилище, инструмент SHALL создавать артефакт инбокса, ссылающийся на путь в хранилище (`from_vault: true`), и SHALL NOT копировать содержимое в репозиторий.

#### Scenario: Крупный скан
- **WHEN** файл в хранилище больше десятков мегабайт
- **THEN** артефакт содержит путь и sha256, а байты остаются в хранилище

#### Scenario: Пропавший файл к моменту разбора
- **WHEN** файл удалён из хранилища после `adopt`
- **THEN** разбор сообщает, что файл не найден, и артефакт нельзя применить

### Requirement: Применение источника переносит файл и вносит запись

`apply` для видов-источников SHALL: сверить sha256, перенести файл из входящих в целевую папку хранилища, проверить запись по схеме и внести источник в `data/sources.json`; при нарушении схемы SHALL вернуть файл на прежнее место.

#### Scenario: Новый источник
- **WHEN** артефакт с видом `personal-letters` применён
- **THEN** файл оказывается в `Исходники/<location>/`, а в `data/sources.json` появляется источник с этим файлом и его sha256

#### Scenario: Файл падает по схеме
- **WHEN** запись источника не проходит схему
- **THEN** файл возвращается во входящие, запись не создаётся, причина пишется в журнал

#### Scenario: Дополнение существующего источника
- **WHEN** при применении указан существующий `--source-id`
- **THEN** файл добавляется в `files` этого источника, а не создаёт второй источник

### Requirement: Виды инбокса покрывают личные материалы

Перечень видов инбокса SHALL включать, кроме документов портала, виды источников личного происхождения: `personal-letters`, `museum-photo`, `archive-reply`.

#### Scenario: Письма через конвейер
- **WHEN** файл подборки писем разбирается через инбокс
- **THEN** вид `personal-letters` допустим, и `apply` вносит источник, а не документ портала
