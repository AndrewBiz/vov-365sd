# Design

## Context

См. `proposal.md`. Текущее состояние: 27 событий, 32 места (20 без координат), 8 документов, 8 источников. Источник `src-loc-lage-ost` зарегистрирован: девять листов Lage Ost за 02.11–06.12.1941, 5 592 × 10 999 px, лицензия LOC свободная. Линии фронта в данных нет, `features.geojson` строится только из событий и мест.

Ограничения:

- Масштаб листа 1:1 000 000 — примерно 1,9 пикселя на километр, точность оцифровки заведомо километровая.
- Проекция листа неизвестна и неоднородна (штабная карта, сшитая из листов); геопривязка по контрольным точкам для каждого листа — отдельная работа, в этом change не делается.
- Января — февраля 1942 в атласе нет: линии ограничены ноябрём и первым днём контрнаступления.
- Оцифровка ручная, поэтому нужна дисциплина: каждая линия — с датой листа, с оценкой точности и с возможностью перепроверки по исходнику.

## Goals / Non-Goals

**Goals:**

- Линия фронта как данные: полилиния, дата, основание, точность.
- Слой GeoJSON и индекс кадров, пригодные для плеера без дополнительной логики.
- Расхождение «дивизия против линии» видно, а не спрятано.

**Non-Goals:**

- Растровая геопривязка листов (warping) и тайловая подложка — отдельный change, когда появится плеер.
- Автоматическое извлечение линии из скана — ручная оцифровка, качество важнее объёма.
- Январь — февраль 1942: источника нет, линий не будет.
- Немецкие и советские линии как разные слои: пока хранится одна линия фронта, обе стороны в атласе уже нанесены на один лист.

## Decisions

**1. Вектор, а не растр.** Линия хранится полилинией в WGS84, а не как отсканированная картинка с привязкой. Причина: анимация требует сравнимых и гладких данных, а растровые листы с неизвестной проекцией дадут «дрожание» при смене кадров. Альтернатива (warping листов) отложена: она дороже и нужна для подложки, не для линии.

**2. Точность — обязательное поле, а не примечание.** Точность в километрах и уровень из реестра («по листу 1:1 000 000», «по схеме», «приблизительно»). Оцифровка с миллионного листа не может быть точнее ±5 км, и это записано в данных. Альтернатива — «примечание про погрешность» — отклонена: примечание не читают, а поле проверяет валидатор.

**3. Дата линии равна дате листа-основания.** Не «примерно тот же день»: провенанс несёт дату листа, и проверка сверяет её с датой линии. Иначе через полгода никто не поймёт, с чего линия снята.

**4. Одна линия на дату, без упрощений на лету.** Сглаживание и упрощение — дело плеера; в данных хранится оцифровка с точками, снятыми вручную (порядка 80–150 точек на лист). Альтернатива — хранить упрощённую версию — отклонена: упрощение необратимо, а исходная оцифровка — это труд, который нельзя терять.

**5. Согласование с событиями — предупреждение, а не ошибка.** Если событие на ту же дату оказывается далеко от линии, это может быть и ошибка оцифровки, и неточность даты события в источнике. Поэтому валидатор сообщает расхождение с расстоянием, но не блокирует сборку; решение — за человеком.

**6. Индекс кадров — отдельный файл, а не вычисление в плеере.** `data/dist/frames.json`: дата → файл слоя, ближайшие события, точность. Плеер не должен угадывать, какие даты есть и в каком порядке.

## Risks / Trade-offs

- [Ручная оцифровка девяти листов — часы работы и субъективность] → фиксированный порядок (снимать по 1–2 точки на 10–15 км вдоль линии), сохранение промежуточных версий в git, повторная сверка по листу на глаз.
- [Проекция листа неизвестна, возможна систематическая ошибка привязки] → пока не привязываем растр вовсе: точки снимаются в географической сетке по самой карте, а погрешность заложена в ±5–10 км; при появлении подложки привязка уточнится.
- [Линия будет «спорить» с событиями (дивизия за линией)] → расхождение выводится списком с расстоянием, а не правится автоматически.
- [После 6.12.1941 анимация обрывается] → индекс кадров честно показывает доступный диапазон; для января 1942 нужен новый источник.
- [Девять листов дают редкие кадры (2–6 дней между датами)] → плеер будет интерполировать; в данных кадры остаются только там, где есть источник.

## Migration Plan

1. Реестр: уровни точности оцифровки, границы театра для проверки.
2. Схема `frontline.schema.json`; пустой каталог `data/front_lines/`.
3. Валидатор и сборка (слой + индекс кадров), тесты.
4. Оцифровка девяти листов, начиная с 06.12.1941 и 28.11.1941 (они нужны для первой версии анимации).
5. README и разбор источника.

Откат: новые файлы аддитивны, события и места не меняются; `git revert`.

## Open Questions

- Нужен ли второй слой — **положение дивизии** (не фронта) на те же даты, снятое с тех же листов? Пока нет: положение дивизии восстанавливается из событий.
- Хранить ли линии противоборствующих сторон раздельно, когда появятся советские карты с более точной обстановкой (1:100 000) — решится при появлении таких карт.
