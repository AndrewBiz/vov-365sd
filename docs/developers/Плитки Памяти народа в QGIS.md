# Плитки «Памяти народа» в QGIS

## Что проверено

- CDN плиток (`cdn.pamyat-naroda.ru`) **отдаёт 401 без сессии**: пробовали без заголовков, с `Referer: https://pamyat-naroda.ru/`, с посторонней кукой — во всех случаях `401` и HTML-страница сайта вместо картинки. То есть авторизация нужна на уровне самих плиток, а не только просмотрщика.
- QGIS умеет XYZ-слои с полем **Referer и таблицей произвольных заголовков** (в сборке 4.2.3 это видно по строке интерфейса «Displays referer HTTP header field and collapsible table of key/value»). Значит `Cookie` технически можно вписать прямо в слой.
- Но: заголовки XYZ-слоя сохраняются в файле проекта. Проект попадает в git — кука утекает в репозиторий вместе с историей. Правило проекта «куки в репозиторий не попадают» это нарушает, поэтому прямой путь не рекомендуем.

## Рекомендуемый путь: локальный прокси

`tools/pn_tile_proxy.py` — маленький HTTP-сервер на localhost: берёт вашу же сессию из отдельного файла, подставляет её в запрос к CDN, кэширует плитки на диск и отдаёт QGIS. В проекте QGIS остаётся только адрес `127.0.0.1`, ни куки, ни токенов.

```bash
python3 tools/pn_tile_proxy.py init     # создаёт ~/.config/365sd/pn.json и пустой файл куки (права 600)
python3 tools/pn_tile_proxy.py check    # проверка сессии на одной плитке, без вывода куки
python3 tools/pn_tile_proxy.py serve    # прокси на 127.0.0.1:8787
python3 tools/pn_tile_proxy.py url      # готовый URL-шаблон для слоя
```

В QGIS: **Слой → Добавить слой → XYZ Tiles → Новое соединение**:

| Поле | Значение |
|---|---|
| Название | `Память народа — 384-0008529-0207/00000002` |
| URL | `http://127.0.0.1:8787/{z}/{x}/{y}.png` |
| Min/Max Zoom | 0 / 15 (лист «Памяти народа» обычно доходит до z13–15) |
| Inverted Y (TMS) | выключено |
| Referer / заголовки | не заполнять: всё это делает прокси |

## Как взять сессию

1. Открыть сайт в своём браузере, дойти до нужной карты (шифр дела и номер листа видны в адресе плитки).
2. F12 → **Network** → фильтр `png` → любой запрос плитки → **Request Headers** → скопировать значение `Cookie` целиком.
3. Вставить в `~/.config/365sd/pn_cookie.txt` (файл уже создан с правами `600`).
4. Поправить в `~/.config/365sd/pn.json` поля `deal` и `page`, затем `check`.

Кука не выводится в консоль и не пишется в лог; прокси сообщает только «сессия принята» или «401 — обновите куки».

## Ограничения и риски

- Сессия живёт ограниченное время и может быть привязана к браузеру. При `401` прокси отвечает понятной ошибкой, а не пустой картой: обновить куку и перезапустить.
- Прокси не обходит проверку безопасности и капчу. Если сайт показал «Проверка безопасности» — это решается в браузере вами, автоматике туда нельзя.
- Массовое скачивание плиток может расходиться с правилами сайта и привести к блокировке аккаунта. Поэтому в прокси по умолчанию 2 одновременных запроса и пауза 150 мс, а всё скачанное кэшируется: повторные проходы в сеть не идут.
- Кэш: `~/.cache/365sd/pn-tiles/<дело>/<лист>/<z>/<x>/<y>.png`. Кэш можно использовать как обычный локальный слой XYZ: `file:///home/anb/.cache/365sd/pn-tiles/384-0008529-0207/00000002/{z}/{x}/{y}.png` — тогда QGIS работает без прокси и без сессии вовсе.

## Когда прокси не нужен

Если лист нужен один раз и целиком, проще скачать плитки штатным `tools/pn_map_grab.js` (в консоли браузера, ваша сессия) или `tools/pn_tiles_stitch.py`, склеить в GeoTIFF и работать с растром: привязка, обводка полос, снятие координат. Живой тайловый слой удобен для просмотра нескольких листов подряд, а не для оцифровки.
