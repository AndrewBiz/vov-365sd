# Задачи для исследователя

Обратный канал к инбоксу: движок говорит, что нужно добыть, зачем, с какой детализацией и в каком виде вернуть. Инбокс принимает то, что уже принесли; задачи говорят, что приносить.

## Команды

```bash
python3 tools/tasks.py sync            # породить задачи из пробелов данных
python3 tools/tasks.py sync --dry-run  # показать, что появится
python3 tools/tasks.py list            # сводка по статусам и приоритетам
python3 tools/tasks.py check           # контракт: обязательные поля, зависимости
python3 tools/tasks.py close <id>      # закрыть — только если ожидаемые файлы на месте
```

## Что где лежит

- `tasks/<id>.md` — задача: YAML-шапка плюс разделы «Зачем», «Что именно», «Чем и как», «Что ждём во входящих», «Когда закрыто».
- `tasks/index.json` — сводка для машинной обработки.
- `~/Documents/Obsidian Vault/Хобби/365сд/Задачи для исследователя/` — зеркало для чтения и отметок с телефона; синхронизируется только через `tasks.py sync`, файлы, исчезнувшие из репозитория, из зеркала убираются.
- `data/calibration/index.json` — состояние привязки листов (`none`, `georef`, `checked`), по записи на лист.

## Генераторы

| Вид | Когда появляется | Что просит |
|---|---|---|
| `georeference-sheet` | у листа карты нет привязки | GCP по градусной сетке, аффинное преобразование, GeoTIFF + `.points`, СКО ≤ 250 м |
| `digitize-places` | есть пункты `unfound`, на которые ссылаются положения или события | координаты центров деревень с привязанного листа, допуск ≤ 250 м |
| `trace-positions` | лист привязан, но положений `basis: map` с него нет | обводка полос частей, подписи и цвет по листу |

Повторный `sync` не создаёт дублей, не перезаписывает задачу в статусе `in-work` (там могли появиться заметки человека) и не трогает закрытые. Если пробел вернулся после закрытия, создаётся новая задача с новой датой — история остаётся.

## Закрытие

`close` проверяет, что обязательные файлы из `expects` лежат во входящих или уже в хранилище. Нет файла — отказ с перечнем недостающего, статус остаётся `open`. Закрытая задача без файла — это исчезнувший из виду пробел, поэтому `--force` только для случаев, когда результат пришёл другим путём и это записано в теле задачи.

## Правила

- Задача не является свидетельством: ни одно её поле не попадает в `data/` как факт. Статусы живут вне датасета, `validate` и `build` задач не видят.
- Имя ожидаемого файла указано заранее — приём не должен требовать догадок. Другое имя не закрывает задачу автоматически.
- Если требуемое невозможно (лист обрезан, пункт на листе не подписан), это пишется в задаче как результат, а не подменяется догадкой: «нет на листе» — нормальный ответ.
