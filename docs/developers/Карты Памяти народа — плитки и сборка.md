# Карты «Памяти народа»: как забрать лист целиком

Проблема: просмотрщик карт на `pamyat-naroda.ru` даёт зумировать, но кнопки «скачать целиком» нет. Кнопка «сохранить оригинал» отдаёт JPEG шириной 3500 px — это **не** максимальное разрешение: при увеличении просмотрщик подгружает плитки крупнее.

## Как устроено

Просмотрщик берёт плитки с CDN:

```
https://cdn.pamyat-naroda.ru/tiles/<шифр дела>/<номер листа>.jpg_tiles/<z>/<x>/<y>.png
```

Пример (из обсуждения сообщества на форуме SAS.Планета):
`https://cdn.pamyat-naroda.ru/tiles/208-0002511-0597/00000002.jpg_tiles/7/74/86.png`

- Схема — **XYZ с перевёрнутой осью Y (TMS)** в Web Mercator (EPSG:3857), плитка 256 px, PNG.
- То есть карта уже привязана: она лежит в тех же координатах, что и подложка Google/OSM. Это подарок: скачав плитки максимального уровня, мы получаем не просто скан, а скан **с готовой привязкой** — GeoTIFF в EPSG:3857.
- Y в схеме считается снизу: `y_tms = 2^z − 1 − y_xyz`. Общинный скрипт для SAS.Planet делает ровно это: `ResultURL := base + (z−1) + '/' + x + '/' + (2^(z−1) − 1 − y) + '.png'`.

## Инструменты проекта

### 1. Быстрый путь: склеить в браузере

`tools/pn_map_grab.js` — вставить в консоль браузера на странице карты (F12 → Console).

1. Открыть карту на портале и подвигать её, чтобы в журнале появились запросы плиток.
2. Вставить скрипт целиком, Enter.
3. Скрипт сам определит шифр дела и лист по загруженным запросам, пройдёт уровни от z=5 вниз по детям найденных плиток, склеит PNG и отдаст файл `<шифр>_<лист>_z<уровень>.png`. В консоль печатается JSON с `bbox_3857` — границы снимка в метрах Web Mercator.

Если шифр не определился — заполнить в скрипте `DEAL` и `PAGE` (взять из DevTools → Network → любая плитка).

### 2. Большие листы: приёмник + GDAL

Когда карта не влезает в canvas браузера, плитки отправляются локальному приёмнику:

```bash
/usr/bin/python3 tools/pn_tiles_stitch.py serve --dir ~/.cache/pn-tiles
# в скрипте браузера: SERVER = 'http://127.0.0.1:8770'
```

Затем сборка:

```bash
/usr/bin/python3 tools/pn_tiles_stitch.py build --dir ~/.cache/pn-tiles --out ~/карты/29А_1942-02
```

На выходе: `29А_1942-02.png`, `29А_1942-02.json` (bbox, zoom, число плиток) и `29А_1942-02.tif` — GeoTIFF в EPSG:3857, который QGIS открывает без привязки.

Требования к сборке: системный `/usr/bin/python3` (в нём есть `osgeo` и `PIL`), пакеты `python-pillow`, `python-numpy`, `gdal`.

### 3. Проверенный обходной путь сообщества

SAS.Планета: файл `params.txt` на каждую карту + `GetURLScript.txt`:

```
begin
ResultURL:=GetUrlBase+inttostr(GetZ-1)+'/'+inttostr(GetX)+'/'+inttostr(round(intpower(2,GetZ-1))-1-GetY)+'.png';
end.
```

`DefURLBase` = адрес до `/tiles/`, то есть `https://cdn.pamyat-naroda.ru/tiles/<шифр>/<лист>.jpg_tiles/`. Диапазон масштабов у карт примерно 7–15.

## Ограничения и честные оговорки

- Скрипт работает **в твоей сессии**: те же запросы, что делает просмотрщик. Защиту портала (проверка «вы человек») он не обходит и обходить не должен — если CDN отвечает 403 вне браузера, значит без сессии плитки не отдаются.
- Привязка плиток — не наша калибровка: её сделал портал. Качество этой привязки мы не проверяли; для линии фронта её можно использовать как черновую, а свои точки ставить по координатной сетке листа (см. `docs/research/Привязка карт — готовые решения и сообщества.md`).
- Максимальный уровень у разных карт разный (7–15). Скрипт останавливается сам, когда у очередного уровня нет дочерних плиток.
