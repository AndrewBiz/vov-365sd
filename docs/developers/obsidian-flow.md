# Хранилище Obsidian и входной конвейер

Документ описывает, как устроено хранилище и как файлы попадают в проект. Правило одно: **оригиналы живут только в Obsidian, репозиторий хранит тексты и ссылки**.

## Структура хранилища

```
Хобби/365сд/
├── Входящие для разбора/            ← сюда кладут новые файлы
└── Исходники/
    ├── ЦАМО — Память народа/        ← сканы портала (по передачам и делам)
    ├── Письма Бизяева Е.М. (1941)/  ← личные материалы, семейные подборки
    ├── Книги и презентации/
    └── Музей Конаково/
```

Папка «Входящие для разбора» — не свалка, а staging: файл лежит в ней, пока не разобран. `apply` переносит его в целевую папку, поэтому входящие очищаются сами.

## Что делает инструмент

```bash
# 1. Что лежит во входящих: размер, sha256, известно или ново
python3 tools/intake.py inbox

# 2. Завести артефакт по файлу из хранилища (файл остаётся на месте)
python3 tools/intake.py adopt "letters-2.pdf" \
    --slug letters-1-2 --kind personal-letters \
    --title "Письма, часть 2: оригиналы" \
    --source-id-new src-bizyaev-letters-1941 \
    --location "Письма Бизяева Е.М. (1941)" \
    --derivative "docs/sources/1941-08-04_Письма с фронта Бизяева ЕМ (август-декабрь 1941).md" \
    --role scans

# 3. Офлайн-разбор: формат, страницы, текстовый слой, OCR, дедуп по sha256
python3 tools/intake.py scan letters-1-2

# 4. Посмотреть, что произойдёт, и применить
python3 tools/intake.py apply letters-1-2 --dry-run
python3 tools/intake.py apply letters-1-2
```

`inbox` ничего не меняет. `adopt` не копирует байты в репозиторий — крупные PDF остаются в хранилище, в артефакте только путь и sha256. `scan` не ходит в сеть. `apply` переносит файл, сверяет sha256 до и после, вносит запись и при ошибке схемы возвращает файл во входящие.

## Два вида артефактов

| Что это | Вид | Куда попадает | Как вносится |
|---|---|---|---|
| Лист дела, карточка портала | `archive-document`, `map-sheet` | `data/documents.json` | `drop` (копия в инбокс) → `scan` → `apply` |
| Подборка, письма, фото музея, ответ архива | `personal-letters`, `museum-photo`, `archive-reply` | `data/sources.json` | `adopt` (без копии) → `scan` → `apply` |

Разница принципиальная: документ портала — единица хранения с реквизитами (фонд, опись, дело, лист); подборка — источник, у которого несколько файлов разных ролей.

## Источник с несколькими файлами

```jsonc
{
  "id": "src-bizyaev-letters-1941",
  "kind": "personal-letters",
  "files": [
    { "path": "Хобби/365сд/Исходники/Письма Бизяева Е.М. (1941)/v2_1-1.pdf",
      "sha256": "7119a0…", "role": "transcription" },
    { "path": "…/v2_1-2.pdf", "sha256": "…", "role": "scans" },
    { "path": "…/v2_1-3.pdf", "sha256": "45d5df…", "role": "photos" }
  ]
}
```

Роли: `original`, `scans`, `transcription`, `photos`, `reference`, `appendix`, `other`. Роль не обязательна, но она объясняет, что открыть, чтобы проверить факт.

Проверка сверяет **каждый** файл. Потерянная часть, несовпавший sha256 и дубль пути внутри источника — ошибки; один файл в двух источниках — предупреждение (фрагмент может входить в две подборки).

## Правила имён

- Оригиналы не переименовываются: имя привязано к sha256, а «улучшение» имени ломает цепочку.
- Замена файла = новая версия источника, а не правка старой записи.
- Производные в репозитории: `docs/sources/<дата>_<тип> <часть> (реквизиты).md`; дата — дата документа, «недат» — если неизвестна.
- В производной первой строкой шапки — путь к оригиналу в хранилище, метод распознавания и кто его выполнил.

## Чего инструмент не делает

- Не ходит в сеть и не обходит защиту порталов.
- Не удаляет файлы из хранилища: только переносит из входящих в целевую папку.
- Не «дочитывает» неразборчивое: `(неразборчиво)` и `[?]` остаются в тексте.
- Не решает за человека, что означает находка: шаг с моделью даёт предложения, применение — отдельная команда.
